# 聚合搜索 MetaSearch

> **不用重新输入**：在搜索结果页（或任何有搜索框的页面）右侧出现一条竖排引擎栏，点一下就把当前搜索词扔给另一个引擎重搜。

单文件用户脚本，无依赖、无构建、无后端。适配 Tampermonkey / Violentmonkey / 脚本猫（ScriptCat）。

## 安装

仓库：[github.com/wioaa/metasearch](https://github.com/wioaa/metasearch)

| 环境 | 方式 |
| --- | --- |
| Tampermonkey / Violentmonkey | 打开 [raw 安装链接](https://raw.githubusercontent.com/wioaa/metasearch/main/metasearch.user.js)，管理器会弹出安装页 |
| 脚本猫（ScriptCat） | 同上；也可在脚本猫里「导入脚本」粘贴文件内容 |
| 只想看效果 | 下载仓库后双击 `demo.html`，无需安装任何扩展 |

脚本猫发布时，`@match *://*/*` 需要在说明里写清权限用途（注入换引擎竖栏），审核会问。

## 它解决什么问题

在 Google 搜完觉得不够，想去 Bing 再搜一次 —— 通常是：复制关键词 → 打开 Bing → 粘贴 → 回车，四步。
这个脚本把它压成一步：**在结果页右侧点一下「Bing」**。

## 搜索词从哪来

按优先级依次尝试，拿到即停：

| 顺序 | 来源 | 说明 |
| --- | --- | --- |
| 1 | 正在输入的搜索框 | 光标在任何搜索框里且已输入内容时，优先用它的值 |
| 2 | URL 查询参数 | `q` / `wd` / `keyword` / `query` / `search_query` / `kw` / `word` / `search`，含 hash 路由里的参数 |
| 3 | 页面上的搜索框 | `input[type=search]`、`name=q/wd/query/keyword`、placeholder 含「搜索 / search」的输入框 |
| 4 | 选中的文字 | 页面上没输入框时，选中一段文字再按 `Alt+S` 也行 |

所以在 Google、百度、Bing、知乎、B站、GitHub 这些站的结果页是自动生效的；在别的地方，只要把词打进页面搜索框，栏会自动跟着出现（边打边更新，250ms 防抖）。

## 位置与宽度：可拖、可预设、带阻力吸附

竖排小窗默认贴在**右边**（结果页右侧通常是留白区，不挡内容），也可以：

- **拖**：按住顶部那行搜索词直接拖走，靠边松手自动吸附
- **⇄**：一键翻到另一边
- **⚙ → 位置**：贴左 / 贴右 / 贴底 / 自由，四个基准位，点完立刻生效并记住
- `自由` 就是停在拖到的地方；`贴左/右` 记纵向位置，`贴底` 记横向位置，换显示器/缩放也不会跑偏

### 宽度

固定宽度在窄屏或内容偏右的站点会压住结果，所以宽度也能调，两条路：

- **拖内侧边沿**：鼠标移到竖栏靠页面那一侧的边缘（会出现一道竖线），左右拖即可，120 ~ 420px
- **⚙ → 宽度滑杆**：精确设值，拖动时实时预览

改宽度时会锁住外侧边沿（贴右时固定右边、贴左时固定左边），窗子不会整体位移，不会出现"我把边拖窄了它却跳走了"。

### 为什么要做「阻力」

离边缘 44px 内松手会吸过去，这是常规做法。但只做吸附会有个问题：**贴着边的时候，手一抖就飞出去**。
所以吸附态下再加一道门槛：

- 从吸附状态开始拖，朝「离开边缘」的方向**必须先移动 26px**，小窗才会真正跟手
- 没到 26px 之前，只按 14% 的比例做橡皮筋位移（拖 10px，窗子动 1.4px），松手弹回原处
- 沿边的方向（比如贴右时上下滑）不受限制，可以直接滑到位

结果就是：贴边状态很稳，想拖走时也很明确 —— 不会出现"我明明只想点，它却跑了"。

### 布局预设（多套）

「贴左 / 贴右 / 贴底 / 自由」只是基准位；平时用的其实是**布局预设** —— 每套记下「基准位 + 位置比例 + 宽度」，一键切换：

- `⚙ → 布局预设` 点一下就应用，**连宽度一起切**；当前匹配的那套会高亮
- `＋ 存当前` 把此刻的位置和宽度存成一套，名字自动生成（例如 `贴右·200`），最多 8 套
- 每套右上角 `✕` 删除
- 预设跟着配置走，也能**单独导出成模板**分享（见下面「配置备份」）

比如：写代码时用 `贴右·窄`（160px）不挡内容，查资料时切 `贴右·宽`（280px）让引擎名别被截断。

### 引擎分组：按用途分类的气泡

按「你现在要干什么」分，而不是按国内/国外。默认 7 组，`⚙ → 引擎分组` 里就是一行可点的气泡：

| 气泡 | 里面都有谁 |
| --- | --- |
| 通用 | 百度、Bing、Google、DuckDuckGo、搜狗、360、Yandex |
| 技术 | GitHub、Stack Overflow、MDN、npm、掘金、CSDN、Hacker News |
| 社区 | 知乎、微博、豆瓣、V2EX、贴吧、Reddit |
| 影音 | B站、YouTube、网易云音乐、腾讯视频、优酷、豆瓣电影 |
| 学术 | 谷歌学术、arXiv、PubMed、Semantic Scholar、知网 |
| 购物 | 淘宝、京东、1688、亚马逊、什么值得买 |
| 图片 | 百度图片、必应图片、Google 图片、Unsplash、Pinterest |

点一下气泡，**整套引擎列表就换掉**，竖栏里的引擎是一个接一个弹进来的；右下角的小数字是这组有几个引擎。

- `＋ 存当前` 把此刻的引擎列表存成一组，默认叫 `自定义 1`，并存完**直接进入改名状态**（回车确认，Esc 取消）
- 悬停气泡出 `✎`（改名）和 `✕`（删除），上限 10 组
- 当前生效的那组会顶起来、描蓝边；引擎列表被单独改过时，没有一个气泡是亮的
- 切分组只换引擎列表，**不动你的搜索词、位置、宽度**

注意这是「换一套列表」，不是「往里加一个」——想混着用，就直接在下面的文本框里增删。

### 栏内就地切换：右上角 ☰

不用每次都开 `⚙`。竖栏右上角那颗 `☰` 点开，引擎列表下面直接展开一排分组小气泡，当前那组是蓝的；点一下整套换掉，弹一下 + 引擎逐个弹入，**面板都不用开**。

- 展开状态存在 `cfg.cats` 里，下次打开还是展开的
- 展开时竖栏会变高，位置会自动重算，不会顶出屏幕
- 分组多的时候气泡区自己滚动（最高 28vh）

## 打开方式可切

栏底有个小按钮，写着当前模式，**点一下切换并记住**：

- **本页** —— 在原标签页直接跳转，相当于「换成这个引擎重搜」（默认）
- **新窗** —— 新标签页打开，原来的结果留着对比

不管哪种模式，中键 / `Ctrl`+点击任一引擎都是新标签打开。

## 使用

| 操作 | 说明 |
| --- | --- |
| 点引擎 | 用当前搜索词在该引擎重搜（按当前打开方式） |
| 拖顶部搜索词 | 移动整个小窗，靠边吸附 |
| 拖内侧边沿 | 调整宽度（120~420px） |
| 点 `本页 / 新窗` | 切换打开方式，立即落盘 |
| 点 `☰` | 就地展开引擎分组气泡，点气泡整组切换（记住展开状态） |
| 点 `⇄` | 贴左 / 贴右互换 |
| 点 `⚙` | 设置：基准位、宽度、布局预设、引擎分组、引擎、快捷键、配置备份 |
| 点 `✕` | 收起（本页不再出现） |
| `Alt+S` | 重新读取搜索词并唤回（可改键） |
| `Esc` | 先关设置面板，再收起竖栏 |

当前页面对应的引擎会**灰掉**（不可点），一眼看出"我现在在哪个引擎"。

## 添加自己的引擎

点 `⚙`，一行一个，格式 `名称 | URL`，`%s` 就是搜索词：

```
百度 | https://www.baidu.com/s?wd=%s
Bing | https://www.bing.com/search?q=%s
Google | https://www.google.com/search?q=%s
DuckDuckGo | https://duckduckgo.com/?q=%s
知乎 | https://www.zhihu.com/search?type=content&q=%s
B站 | https://search.bilibili.com/all?keyword=%s
GitHub | https://github.com/search?q=%s
维基 | https://zh.wikipedia.org/w/index.php?search=%s
```

规则很宽松：

- `#` 开头的行是注释，不会被保存
- **不写名称**就直接写 URL，名称自动取域名（`https://x.com/?q=%s` → `x.com`）
- 行序 = 竖栏里的顺序，想换位置就调换行
- 保存时校验：URL 必须以 `http(s)://` 开头、必须含 `%s`，否则拦下并提示是哪一条
- 直接把整段贴给别人，对方粘贴进设置框保存即可

更多模板：

| 站点 | URL 模板 |
| --- | --- |
| 搜狗 | `https://www.sogou.com/web?query=%s` |
| 360 搜索 | `https://www.so.com/s?q=%s` |
| 微博 | `https://s.weibo.com/weibo?q=%s` |
| 豆瓣 | `https://www.douban.com/search?q=%s` |
| MDN | `https://developer.mozilla.org/zh-CN/search?q=%s` |
| YouTube | `https://www.youtube.com/results?search_query=%s` |
| 淘宝 | `https://s.taobao.com/search?q=%s` |
| 公司内网 Confluence | `https://wiki.example.com/dosearchsite.action?queryString=%s` |

## 配置字段

存在 `GM_setValue('metasearch:cfg')` 里，是一份 JSON，方便手动改或分享：

```json
{
  "hotkey": "alt+s",
  "openNew": false,
  "cats": false,
  "w": 172,
  "pos": { "m": "right", "x": 0.5, "y": 0.5 },
  "presets": [
    { "name": "贴右·窄", "m": "right", "x": 0.5, "y": 0.5, "w": 160 },
    { "name": "贴右·宽", "m": "right", "x": 0.5, "y": 0.5, "w": 280 }
  ],
  "groups": [
    { "name": "技术", "engines": [
      { "name": "GitHub", "url": "https://github.com/search?q=%s" },
      { "name": "MDN", "url": "https://developer.mozilla.org/zh-CN/search?q=%s" }
    ] }
  ],
  "engines": [
    { "name": "百度", "url": "https://www.baidu.com/s?wd=%s" },
    { "name": "Bing", "url": "https://www.bing.com/search?q=%s" }
  ]
}
```

| 字段 | 说明 |
| --- | --- |
| `hotkey` | 唤起快捷键，必须带修饰键 |
| `openNew` | `false` 本页跳转 / `true` 新标签打开 |
| `cats` | 竖栏里是否展开分组气泡 |
| `w` | 竖栏宽度 px，120~420 |
| `pos.m` | `left` / `right` / `bottom` / `free` |
| `pos.x` / `pos.y` | 0~1 的比例位置，换分辨率不跑偏 |
| `presets[]` | 布局预设，`name` 可省（自动按 `贴右·172` 生成），最多 8 套 |
| `groups[]` | 引擎分组气泡，每组一套 `engines`，最多 10 组；`name` 建议 12 字内 |

## 配置备份 / 分享

`⚙` 面板底部的「配置备份」区，分三类各管一段：

| 按钮 | 作用 |
| --- | --- |
| 导出整份 | 引擎 + 分组 + 快捷键 + 位置 + 宽度 + 布局预设 → `metasearch-config.json`，同时回填到下面文本框 |
| 导出布局 | **只导出布局预设** → `metasearch-layout.json`，单独分享一套摆法 |
| 导出引擎 | **只导出引擎 + 分组** → `metasearch-engines.json`，分享一整套搜索习惯 |
| 导入文件 | 选 `.json`，按内容自动认类型（整份 / 布局 / 引擎），然后走对应的写入 |
| 写入配置 | 把文本框里的 JSON 整份写入（粘贴别人的配置后点这个） |
| 写入布局 | 只写 `presets`，引擎、分组、快捷键都不动 |
| 写入引擎 | 只写 `engines` 和 `groups`，布局与快捷键都不动 |

几个细节：

- 导出内容都是纯 JSON，可以直接贴进 issue；文件下载失败的环境（比如某些内嵌预览）会自动留在文本框里，手动复制即可
- 写入前统一走一遍校验：引擎缺 `%s`、缺 `http(s)://`、预设为空都会被拦下并提示
- 「写入布局」只改布局，「写入引擎」只改引擎与分组 —— 套用别人的模板不会覆盖你自己配的那一半
- 位置 / 宽度 / 预设是**即时生效**的，点「保存」只提交引擎和快捷键，不会把刚调好的布局冲掉

## 实现上的取舍

- **不做结果抓取**：不解析各家 SERP 的 HTML，也不发任何网络请求。只负责「把词带过去」，页面加载交给浏览器。改版打不挂、不需要 `@connect` 权限、也不会因为风控被挡。
- **不用 `window.open`**：引擎就是真 `<a href>`，中键、`Ctrl`+点击、右键新标签全都原生可用，也不会触发弹窗拦截。
- **位置用比例存**：`{m, x, y}`，x / y 是 0~1。换分辨率、开侧边栏、页面缩放都不会把窗子甩到屏幕外。
- **Shadow DOM + CSSOM 注入样式**：不受目标站样式污染，也不怕 strict CSP 把 `<style>` 拦掉（老浏览器自动退回 `<style>`）。
- **只在顶层窗口运行**（`@noframes`），不读页面内容；`input` 事件只对搜索框响应，拖拽时会 `stopPropagation`，不干扰页面自己的手势。

## 已知限制

- 少数站点的搜索框是 `contenteditable` 或纯前端自绘的，读不到 `value`；此时用 `Alt+S` 让它改读 URL 参数或选中文字。
- 拖到屏幕正中间也可以，但会挡住内容 —— 这是自由摆放的代价，拖回边上即可。
- 单页应用切换路由时靠 `popstate` / `hashchange` 重读；若某站用纯 `pushState` 且不触发事件，按一下 `Alt+S`。
- 默认快捷键 `Alt+S` 会和少数站点冲突，在设置里录新组合即可。

## 这个项目是怎么写出来的（Vibe Coding）

这是一个 **Vibe Coding 项目**：需求用自然语言提，代码由 AI 代理（WorkBuddy）生成，人只在关键处拍板。没有逐行手写、没开 IDE 补全，连提交和发布都是在对话里完成的。

留下这一节不是记流水账，而是因为有个规律很明显：**返工几乎全发生在方向上，不在代码上**。一天里改了六轮，没有一轮是"bug 修不动"，全是"做出来的东西不是想要的东西"。

四条能复用的：

1. **人定方向，AI 定实现。** 栏贴在哪、这一步交互要不要、手感对不对，只能人来判断；换成什么定位模型、位置用什么坐标系存、动画怎么才能重播，交给 AI 更快。
2. **一次只改一个维度。** 位置 → 可拖 → 宽度 → 预设，四件事分开提、每件当场看效果。攒在一起提，改完就分不清是哪一步起的作用。
3. **视觉和手感只能人验。** 26px 的脱离门槛、0.14 的阻尼、172px 的默认宽度，AI 只能给个合理起点，必须在真浏览器里拖两下才知道黏不黏、挡不挡。
4. **测试兜得住逻辑，兜不住意图。** 115 条 jsdom 断言能保证「改宽度时右边沿不动」，但保证不了「这个宽度是否挡内容」。

以及它的边界：AI 最擅长**把结构改对**（换定位模型、换坐标系、重排数据流），最不擅长**猜你想要什么**。所以沟通上有效的做法是先说"不要什么"——排除项比期望项更容易一次说对。
